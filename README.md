## المشكلة

في مجال الأمن السيبراني، يحتاج المتخصصون والمختبرون إلى أدوات استطلاع (Reconnaissance) تساعدهم في جمع المعلومات حول الأهداف قبل إجراء اختبار الاختراق أو تقييم الأمان. المشكلات الحالية:

- **الاعتماد على مكتبات خارجية**: معظم الأدوات المتاحة تعتمد على مكتبات خارجية مثل `requests` و `dnspython` و `urllib3`، مما يزيد من تعقيد التثبيت والإدارة.
- **صعوبة التشغيل**: العديد من الأدوات تتطلب بيئات معقدة وتثبيت مكتبات متعددة.
- **غياب الواجهة الواضحة**: بعض الأدوات تفتقر لواجهة سطر أوامر واضحة وسهلة الاستخدام.
- **ضعف معالجة الأخطاء**: ظهور رسائل خطأ برمجية (Tracebacks) غير مفهومة للمستخدم.
- **عدم التوافق**: بعض الأدوات تعمل على نظام واحد فقط دون دعم متعدد للأنظمة.

## فكرة المشروع

بناء أداة استطلاع أمني شاملة (**ReconGuard**) تعمل بـ **Pure Python** باستخدام **المكتبات القياسية فقط** (Standard Library)، وتوفر مجموعة متكاملة من وظائف الاستطلاع الأمني:

- **استطلاع DNS**: استعلام عن سجلات A, AAAA, MX, NS, TXT, CNAME, SOA
- **معلومات WHOIS**: استخراج معلومات النطاق عبر سجلات SOA
- **استطلاع HTTP**: فحص النقاط النهائية (Endpoints) واكتشاف التقنيات
- **معلومات SSL/TLS**: فحص الشهادات الرقمية وتواريخ انتهائها
- **فحص المنافذ**: مسح المنافذ المفتوحة وتحديد الخدمات
- **اكتشاف النطاقات الفرعية**: البحث عن Subdomains
- **التحديد الجغرافي للـ IP**: تحديد موقع ومزود الخدمة
- **استخراج الأنماط**: البحث عن الأسرار والمفاتيح والبيانات الحساسة
- **تحويل JSON**: تحويل بيانات API إلى مخطط موحد
- **تقارير شاملة**: توليد تقارير بصيغة JSON و Markdown

## الهدف

- توفير أداة استطلاع أمني **تعمل بـ Pure Python** دون أي مكتبات خارجية
- تنفيذ **بروتوكول DNS الخام** (Raw DNS Protocol) من الصفر باستخدام Sockets
- تنفيذ **DNS-over-HTTPS (DoH)** كبديل موثوق يعمل في الشبكات المقيدة
- توفير واجهة **CLI احترافية** مع أوامر فرعية وخيارات قياسية
- **معالجة شاملة للأخطاء** دون إظهار Tracebacks للمستخدم
- **توافق كامل** مع نظامي Windows و Linux
- توليد **تقارير احترافية** بصيغتي JSON و Markdown
- دعم **الفحص المتزامن** (Concurrent Scanning) لعدة أهداف

## الميزات

### استطلاع DNS المتقدم
- تنفيذ بروتوكول DNS الخام (RFC 1035) من الصفر عبر UDP
- تنفيذ DNS-over-HTTPS (DoH) باستخدام Google DNS و Cloudflare DNS و Quad9
- استعلام عن جميع أنواع السجلات: A, AAAA, MX, NS, TXT, CNAME, SOA
- آلية Failover: DoH أولاً، ثم UDP كاحتياطي

### استطلاع HTTP
- فحص النقاط النهائية (Endpoints) المخصصة
- اكتشاف التقنيات (Nginx, Apache, Cloudflare, WordPress, وغيرها)
- فحص رؤوس الأمان (Security Headers)
- دعم HTTP/HTTPS مع Failover
- تتبع إعادة التوجيه (Redirects)

### فحص SSL/TLS
- استخراج معلومات الشهادة الرقمية
- تاريخ الإصدار والانتهاء
- اسم المُصدر والموضوع
- Subject Alternative Names (SAN)
- الرقم التسلسلي للشهادة

### فحص المنافذ
- مسح متزامن للمنافذ (Async TCP Connect Scan)
- تحديد الخدمات المعروفة
- تحكم في مستوى التزامن (Concurrency)
- دعم 29 منفذ شائع افتراضياً

### استخراج الأنماط (Secret Extraction)
- اكتشاف مفاتيح AWS (Access Key ID)
- اكتشاف مفاتيح Google API و Firebase و OAuth
- اكتشاف JWT Tokens
- اكتشاف Facebook Access Tokens
- اكتشاف Stripe API Keys
- اكتشاف Twilio API Keys
- اكتشاف Slack Tokens
- اكتشاف GitHub Access Tokens
- اكتشاف RSA Private Keys
- اكتشاف البريد الإلكتروني وعناوين IP الداخلية
- اكتشاف كلمات المرور المحتملة

### تقارير شاملة
- تقرير JSON تفصيلي
- تقرير Markdown منسق
- ملخص تنفيذي مع الإحصائيات
- معلومات البيئة (نظام التشغيل، إصدار Python)

## متطلبات التشغيل

- **Python 3.8+** (لا حاجة لأي مكتبات خارجية)
- **لا حاجة لتثبيت أي pip packages**
- نظام التشغيل: Windows أو Linux

## طريقة التشغيل

### 1. إنشاء ملف الإعدادات

```bash
python3 recon_guard.py init-config
```

سيتم إنشاء ملف `config.json` في المجلد الحالي. قم بتعديله لتحديد الأهداف.

### 2. تشغيل المسح الكامل

```bash
python3 recon_guard.py scan
```

### 3. تشغيل مسح بأوامر فرعية محددة

```bash
# مسح DNS فقط
python3 recon_guard.py dns example.com

# استطلاع HTTP فقط
python3 recon_guard.py http example.com --endpoint robots.txt

# فحص المنافذ فقط
python3 recon_guard.py ports example.com

# اكتشاف النطاقات الفرعية فقط
python3 recon_guard.py subdomains example.com
```

### 4. استخراج الأسرار من ملف

```bash
python3 recon_guard.py extract secrets.txt --output findings.json
```

### 5. تحويل بيانات API

```bash
python3 recon_guard.py transform input.json output.json
```

## ملف الإعدادات

ملف `config.json` يحتوي على الإعدادات التالية:

```json
{
    "target_domains": ["example.com", "github.com"],
    "target_endpoint": "robots.txt",
    "additional_endpoints": ["sitemap.xml", ".env", "wp-admin/", ...],
    "http_timeout": 15,
    "max_concurrent_targets": 5,
    "common_ports": [21, 22, 80, 443, 3306, ...],
    "port_services": {"21": "FTP", "22": "SSH", "80": "HTTP", ...},
    "common_subdomains": ["www", "mail", "admin", "api", ...],
    "custom_regex_patterns": null

```

### شرح الحقول

| الحقل | النوع | الوصف |
|-------|------|-------|
| `target_domains` | قائمة | النطاقات المستهدفة للفحص |
| `target_endpoint` | نص | النقطة النهائية الأساسية للفحص |

| `port_scan_concurrency` | رقم | مستوى تزامن فحص المنافذ |
| `port_scan_timeout` | رقم | مهلة اتصال المنفذ بالثواني |
| `subdomain_concurrency` | رقم | مستوى تزامن اكتشاف النطاقات الفرعية |
| `dns_timeout` | رقم | مهلة استعلام DNS بالثواني |

| `common_ports` | قائمة | المنافذ المراد فحصها |
| `port_services` | كائن | خريطة المنافذ إلى أسماء الخدمات |
| `common_subdomains` | قائمة | النطاقات الفرعية المراد تجربتها |
| `custom_regex_patterns` | كائن | أنماط Regex مخصصة (null = افتراضي) |

## النتائج والمخرجات

### تقرير JSON (`report.json`)
يحتوي على:
- بيانات وصفية (الطابع الزمني، النظام، إصدار Python، المدة)
- نتائج كل هدف (HTTP, DNS, WHOIS, IP/Geo, SSL, Ports, Subdomains)
- فحص رؤوس الأمان
- نتائج استخراج الأنماط

### تقرير Markdown (`report.md`)
تقرير منسق وسهل القراءة يحتوي على:
- ملخص التنفيذ
- تفاصيل كل هدف مع أقسام منظمة
- جداول النتائج
- ملخص استخراج الأنماط

### مثال على التقرير

```
ReconGuard — Security Reconnaissance Report

Target: example.com

### HTTP Reconnaissance
- URL: https://example.com/robots.txt
- Status Code: 404
- Technologies: Cloudflare

### Security Headers
- Security Score: 0/8
- Missing: HSTS, CSP, X-Frame-Options, ...

### DNS Records
- A: 104.20.23.154, 172.66.147.243
- NS: elliott.ns.cloudflare.com, hera.ns.cloudflare.com
- TXT: v=spf1 -all

### SSL Certificate
- Subject: Unknown
- Issuer: Unknown
- Valid Until: Oct 27 22:17:21 2026 GMT
- SAN: example.com, *.example.com
```

## معالجة الأخطاء

الأداة تعالج جميع الأخطاء المتوقعة بشكل مناسب:

| نوع الخطأ | المعالجة | رمز الخروج |
|-----------|---------|-----------|
| ملف إعدادات غير موجود | رسالة واضحة | 2 |
| ملف إعدادات تالف (JSON غير صالح) | رسالة واضحة | 2 |
| نطاق غير صالح | رسالة تحذير وتخطي | - |
| ملف غير موجود | رسالة واضحة | 1 |
| فشل الاتصال | رسالة واضحة | 4 |
| انتهاء مهلة الاتصال (Timeout) | رسالة واضحة | 4 |
| عدم كفاية الصلاحيات | رسالة واضحة | 5 |
| فشل كتابة التقرير | رسالة واضحة | 6 |
| إلغاء المستخدم (Ctrl+C) | رسالة إلغاء | 130 |
| خطأ غير متوقع | رسالة واضحة + خيار التفاصيل | 1 |

لا تظهر أي Tracebacks برمجية للمستخدم إلا عند استخدام `--log-level DEBUG`.

## التوافق مع أنظمة التشغيل

- **Linux**: مدعوم بالكامل
- **Windows**: مدعوم بالكامل (مع مراعاة اختلاف المسارات)
- **macOS**: مدعوم بالكامل

الأداة تستخدم `pathlib.Path` للتعامل مع المسارات بشكل متعدد المنصات، وتستخدم `platform` للكشف عن النظام.

> **ملاحظة حول فحص المنافذ**: يعتمد فحص المنافذ على TCP Connect Scan، وقد تظهر نتائج إيجابية خاطئة (False Positives) في البيئات التي تحتوي على Proxy أو Firewall يقبل جميع الاتصالات. يُنصح باختبار الأداة على هدف محلي أو مصرح به للتأكد من دقة النتائج.

### تنفيذ بروتوكول DNS الخام

تم تنفيذ بروتوكول DNS (RFC 1035) من الصفر:

1. **بناء حزمة الاستعلام**: Transaction ID + Flags + Question Section
2. **ترميز أسماء النطاقات**: تحويل النطاق إلى تسلسل Labels
3. **تحليل الاستجابة**: قراءة Header + Question + Answer Sections
4. **دعم Compression Pointers**: التعامل مع ضغط أسماء DNS
5. **تحليل جميع أنواع السجلات**: A, AAAA, NS, CNAME, MX, TXT, SOA

### تنفيذ DNS-over-HTTPS (DoH)

كطريقة أساسية للاستعلام، يتم استخدام DoH عبر:
- Google DNS: `https://dns.google/resolve`
- Cloudflare DNS: `https://cloudflare-dns.com/dns-query`
- Quad9 DNS: `https://dns.quad9.net:5053/dns-query`
